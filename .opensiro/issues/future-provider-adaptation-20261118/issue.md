## 1. Why OpenSiro

OpenSiro investigates whether **standardized VSM-informed organizational capabilities**, reused through the *original harness's own native mechanisms*, can reduce implementation, validation, maintenance and integration costs. VSM ownership labels are diagnostic, **not** product scores or commands to create a controller for each missing letter. Unmeasured savings are a hypothesis.

## 3. Proposed user task and native alternative

**Candidate P0 task (not yet a qualified feature):** when a trusted vendor announces a *future* model/provider deprecation that affects a deployed city, a developer configures a bounded autonomous agent to choose among approved `retain/migrate/hold` options, guard application to later eligible sessions and observe actual subsequent session/task feedback.

**Current original-native alternative:** [root/rig provider patches](https://github.com/gastownhall/gascity/blob/03f6fe825cf0a54c677c241e4aaa7e76dade28a5/docs/guides/gastown-config-recipes.md), [agent model/upstream config](https://github.com/gastownhall/gascity/blob/03f6fe825cf0a54c677c241e4aaa7e76dade28a5/docs/guides/configuring-an-agent.md), [orders on condition/event/schedule](https://github.com/gastownhall/gascity/blob/03f6fe825cf0a54c677c241e4aaa7e76dade28a5/docs/tutorials/07-orders.md), [formula/agent composition](https://github.com/gastownhall/gascity/blob/03f6fe825cf0a54c677c241e4aaa7e76dade28a5/docs/getting-started/how-gas-city-works.md), and [revision-aware config reload](https://github.com/gastownhall/gascity/blob/03f6fe825cf0a54c677c241e4aaa7e76dade28a5/cmd/gc/cmd_reload.go). These are shipped entry points, but **not yet a demonstrated autonomous five-link S4 witness**.

**What the user would gain beyond this:** fewer manual changes to a future-provider migration with preserved authorizations and better later-session accuracy. No named actual prospective provider retirement, affected real deployment, failed native comparator or all-in savings was established in this analysis. Thus **GO is unsupported**.

## 6. What could legitimately reopen a narrowly scoped roadmap

A concrete operator/developer reports an actual **future** provider/model change, multiple lawful compatible choices and an adverse observable outcome from manually configured or native pack-based migration. That owner supplies the real signal and needed operator policy. First-party experimental implementation is **separately authorized**; a provider adapter is added only if the supported native composition **fails** a reproducible end-to-end case. The AI companion defines decisive positive/negative tests and source ownership.
