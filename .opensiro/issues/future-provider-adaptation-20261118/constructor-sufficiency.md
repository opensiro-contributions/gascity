## 2. System and real candidate hypothesis

**Unit:** one Gas City installed city, its native agent worker/rigs, bundled core pack, orders, formulas, work-beads, config editor and controller/reconciler. The environmental vendor and its model releases are outside; legal provider/credential and S5 rights belong to the operator/higher policy owner. User tasks are first-party project work, not OpenSiro methodology grades.

**Candidate S4 disturbance:** a verifiable provider/model future deprecation before immediate session failure, with effective date, affected workers and candidate compatible alternatives. **Not** current HTTP 429 retry, model alias spelling or present capacity.

**Narrow baseline:** an operator manually changes approved `[[patches.agent]]` model/provider and runs/reviews native config reload, while existing [orders](https://github.com/gastownhall/gascity/blob/03f6fe825cf0a54c677c241e4aaa7e76dade28a5/docs/tutorials/07-orders.md) can trigger a bounded formula; the [config editor](https://github.com/gastownhall/gascity/blob/03f6fe825cf0a54c677c241e4aaa7e76dade28a5/internal/configedit/configedit.go) validates and writes state. This may be enough for actual users. No test has established its insufficiency.

## 3. Conditional future five-port S4 constructor (proposed, not shipped)

| Port | Native port hypothesis | Decisive owner / failure condition |
| --- | --- | --- |
| S4-A external/prospective signal | Verified dated model retirement in opt-in order/agent input, external source pinned | No present-only quota failure or invented future vendor fact |
| S4-B lawful options | Resolve compatible provider/model, credentials, explicit allowed scope, expected revision | Must not autonomously extend approved provider or budget rights |
| S4-C real developer-composed decision | Configured bounded future-policy agent chooses `retain`, `migrate`, or `hold` based on A+B | No installed actor → no fabricated `C`; deterministic fallback alone insufficient |
| S4-D authorized future effect | Operator-approved scoped patch / revision guard / normal reload into **later eligible** session | Do not overwrite concurrent operator edits, leak secrets, interrupt active worker, or claim cross-process CAS from a mutex |
| S4-E return to S3 | Durable decision receipt joined to a **real later** session's effective provider/model and task result/failure | Reload accepted or an event emitted is **not** proof the new task succeeded |

**Proposed complete sufficiency only:** all five first-party reachable links in a supported distribution, developer-instantiable autonomous choice and two legitimately different outcomes under bounded authority. A generic scheduler, webhook, agent prompt or shell command alone does not establish S4=C.

## 6. Terminal decision and resumption rule

**NO_GO** now. Current first-party signals show generic composability and narrower owner Issues, but no named qualified prospective consumer and no supported native failure requiring a new SDK port. The accepted S4=— is **not a product requirement by itself**. S3=P and S5=— do not automatically become P2 feature programs.

**NEEDS_EVIDENCE** describes the future optional capability question, not an instruction to pause this completed roadmap. Reopen *another narrowly scoped* case only with a real future disturbance, legitimate user, evidence that native baseline fails, minimal first-party port, executable positive/negative tests and measured/grounded difference. No automatic public original/fork Issue, PR or release code authorized.
